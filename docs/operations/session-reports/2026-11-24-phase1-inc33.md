# Session report: Phase 1, increment 33 (2026-11-24)

## Delivered
- Member self-service API at `/api/v1/member` for a USSD or mobile front end: overview of own
  accounts and loans, savings statement, loan schedule with payoff quote, M-Pesa payment prompt
  to own loan or savings account, and the prompt's status. ADR-0033.
- Member tokens (role MEMBER, `customer_number` claim) reach only the member API; staff APIs refuse
  them and the member API refuses staff.
- V30: payment prompts linked to a member are checked by the database (active member, own phone,
  own account or loan, link never changes). Database test MS1.
- Limits: 3 prompts per member per 10 minutes (database-counted) and a per-minute request limit;
  both return 429 with Retry-After.
- Member requests are audited as `member:<subject>`.
- Architecture test: every endpoint must declare a role check.

## Issues found and fixed
- A hand-written access rule for staff APIs would have let anonymous requests through; it now
  requires a real authentication as well as "not a member".
- The request audit recorded members as `user:<subject>`; it now uses `member:<subject>`, matching
  the payment record.
- A test helper's authority list did not compile (generic type); fixed.

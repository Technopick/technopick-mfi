# Session report: Phase 1, increment 11 (2026-11-18)

## Delivered
- **STK reconciliation (V11)**: core housekeeping job (expire undispatched, flag unknown sends),
  STK status queries from the integration runtime, attention list for operations; a "paid" query
  answer never credits without a receipt.
- **B2C loan disbursement (V12)**: maker-checker request/approval, one live disbursement per loan,
  single dispatch, SecurityCredential encryption, result and queue-timeout callbacks (store then
  ack), posting + loan activation only on a matching success, alarms for timeout, amount mismatch
  and success after failure; attention list; housekeeping flag for unknown sends.
- `LoanDisbursementService` in lending (posting + activation through the accounting port).
- Simulator: B2C v3 with RSA key pair (credential really decrypted), STK query scenarios.
- New architecture rule: API types must have unique simple names.
- OpenAPI: 13 paths and 13 schemas added across the increment, nothing existing changed.
- ADR-0012, ADR-0011 updated, runbook `docs/operations/daraja-b2c-setup.md`.

## Test evidence (CI, all four jobs green)
Linux: canonical 16, core 84 (11 end-to-end), simulator 2, integration 10. Windows: 16 + 73 + 2.
Database: 83/83.

## Issues found and fixed
- Database rule caught event type names with a digit (`MpesaB2c...`) -> renamed to
  `MpesaDisbursementApproved` / `MpesaDisbursementFailed`.
- Contract review caught B2C API types silently merged with STK types of the same name (wrong
  documented shapes) -> renamed; new architecture rule prevents it; it immediately caught a third
  clash (`Status`).
- Reconciliation test credited a shared test account and broke another test's balance check ->
  dedicated account.

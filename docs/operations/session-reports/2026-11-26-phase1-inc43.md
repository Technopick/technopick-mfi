# Session report: Phase 1, increment 43 (2026-11-26)

## Delivered
- V40: loan limit rules per product and loan guarantees, with the rules enforced in the database:
  `lending.loan_limit` (own cover = savings less pledges for others plus shares if counted; limit =
  multiple x own cover less other loans outstanding if deducted); approval refused above the limit
  or with guarantees short of the part above own cover; guarantees only on open applications, by
  another active member, from their own active account, locked by a matching EARMARK hold they can
  afford; holds released only with their guarantee; pledges withdrawn only while the application is
  open; released automatically when the application is declined or withdrawn or the loan closes.
  Member exit now names open guarantees.
- Core: LoanLimitService and API (rules, a member's limit, application cover, pledge, withdraw,
  guarantees given by a member); limits checked at submission and approval in the origination
  service with plain explanations.
- Staff app: "Limit and guarantors" panel on the application page (own cover, limit, guarantees
  needed and pledged, add and withdraw guarantors) and a "Loan limits" page (rules by product,
  editable by finance). ADR-0043.
- Browser journey: the loan journey checks the panel on the application page.

## Issues found and fixed
- The test product allows 3 to 24 months; the database test first used 1 month.
- The staff app's API client has no DELETE, so removing a rule is a POST to `/remove`.
- Legacy applications without a customer link are not limit-checked (no member to measure).

## Decisions needed

  called on when a loan defaults.

# Session report: Phase 1, increment 45 (2026-11-26)

## Delivered
- Backup (`mfi-backup.sh`): pg_dump custom format as a read-only `mfi_backup` role (BYPASSRLS +
  pg_read_all_data), optional encryption to a public key, roles without passwords, a fingerprint read
  in the same exported snapshot as the dump, checksums, a manifest, an optional node_exporter metrics
  file, and opt-in pruning (off by default).
- Restore (`mfi-restore-verify.sh`): checksums, missing roles recreated without passwords, restore
  only into a new database in one transaction, fingerprint compared line by line, independent checks
  (migrations, journal entries balanced and with lines, audit chains, business dates); `--verify-only`
  compares a database with a backup without changing it.
- TEST-ONLY drill in CI (new job, PostgreSQL 17 tools) and a manual drill at load-test scale.
- V42: `ops.health_snapshot()` and `ops.audit_chain_status()`, counts only, per active tenant.
- Core: Prometheus registry; `OperationalHealth` publishes per-tenant gauges, refreshed every minute
  (audit chains hourly); `/actuator/prometheus` for the MONITORING role only.
- Alert rules (16) with promtool unit tests (new CI job); runbooks for backup and restore, and for
  monitoring with a section per alert. ADR-0045.

## Issues found and fixed
- `pg_dumpall -d` takes a connection string; the database is given with `-l`.
- The snapshot-holding psql session never ended (its input stayed open in the shell); it now quits.
- A fingerprint difference stopped the restore script before the independent checks ran
  (`pipefail` on `diff`); all checks now run and are reported.
- `eod_days_behind` was missing for a tenant with no business date; it is now reported empty.
- One end-to-end run failed because Maven Central answered 429 (rate limit); the rerun passed.
